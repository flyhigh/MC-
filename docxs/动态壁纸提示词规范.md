# 动态壁纸图生视频提示词规范

> 适用模型：智谱 CogVideoX-3 / CogVideoX 系列图生视频
> 研究日期：2026-10-17
> 结论：动态壁纸的提示词不是“让画面动起来”，而是一份**锁死镜头、指定实体运动**的说明书。

## 0. 先给结论

一条能出片的动态壁纸提示词，必须同时满足下面 7 件事：

1. **镜头锁死**：不写推、拉、摇、移、环绕、变焦、手持、航拍。镜头一动，模型就会用“推近”伪造运动。
2. **写实体，不写光影**：至少 2~3 个真实物体会动，例如草、树叶、云、水、雨、车流、人群、衣摆、头发、烟、火焰。
3. **前景优先**：先写离镜头最近的草/花/衣摆，再写中景的树/车/人，最后写天空的云/鸟。模型对前几句最敏感。
4. **动作要有方向/幅度/节奏**：不要写 `sway gently`，写 `bend deeply in visible waves from left to right`；不要写 `clouds move`，写 `thin clouds stream steadily across the sky`。
5. **不写“seamless loop”**：CogVideoX 不是天然循环模型。循环靠播放器在最后 0.6~1.0 秒淡回首帧，提示词只负责让元素持续运动。
6. **不写时间/光线词**：`sunset`、`dusk`、`golden hour`、`warm sunlight` 会把模型带向整体明暗和色调变化，而不是实体运动。原图已经有光线，提示词只锁曝光和色彩。
7. **守住 512 字符**：CogVideoX-3 的 `prompt` 硬上限是 512 个字符（不是 512 个词），英文大约 75~85 词。约束句写太长，就没有字符写运动了。

一句话模板：

```text
[场景锚点] + [前景实体动作] + [中景实体动作] + [远景/天空动作] + [固定机位] + [保持约束] + [连续运动]
```

## 1. 资料结论：官方到底要求什么

### 1.1 CogVideoX 官方仓库：长提示词，质量直接决定成片

官方 README 在 Prompt Optimization 一节写得很直接：

> the model is trained with long prompts, and a good prompt directly impacts the quality of the video generation.

来源：[zai-org/CogVideo README](https://github.com/zai-org/CogVideo)

这说明两件事：

- 不要只写“让画面动起来”这种短指令；
- 但“长”不等于堆形容词，而是**信息密度**：场景、实体、动作、方向、约束要具体。

### 1.2 官方图生视频脚本：输入图就是第一帧

官方 `inference/convert_demo.py` 里的 i2v 系统提示词，要求非常明确：

- 输入图就是视频的**第一帧**；
- 提示词要**高度描述画面**，并补充合理的动态信息；
- 描述**从当前画面开始发生的运动**；
- **不要镜头转场、不要切屏、不要透视变化**；
- 用完整句子，直接开始，不要写 `The image/video showcases...` 这类开场；
- 官方脚本要求输出英文。

来源：[convert_demo.py](https://github.com/zai-org/CogVideo/blob/main/inference/convert_demo.py)

这条资料是“动态壁纸不能写运镜”的最硬依据：官方 i2v 脚本本身就不希望模型做镜头转场和透视变化。

### 1.3 CogVideoX-3 文档与 API：512 字符是硬上限

| 项目 | 官方说明 | 对动态壁纸的意义 |
|---|---|---|
| 输入 | 图像、文本、首尾帧 | 单图首帧最适合自然动态；首尾帧适合受控转场 |
| 时长 | 5s / 10s | 5s 更适合测试循环；10s 更自然但更容易漂移 |
| 分辨率 | 最高 4K | 按屏幕比例选，不要为了“大”牺牲稳定性 |
| 模式 | `quality` / `speed` | `quality` 更听话；`speed` 运动可能更明显 |
| prompt | **不能超过 512 个字符** | 英文约 75~85 词；约束句要短 |
| image_url | 与 prompt 不能同时为空 | 图生视频必须给图 |
| size | 默认短边 1080，最高 4K | 用接口枚举里的七档，别自己算奇怪比例 |
| fps | 30 / 60 | 30 足够；60 更顺但更贵/更慢 |
| duration | 5 / 10 | 当前代码用 10，建议测试 5 |
| quality 默认 | `speed` | 当前代码显式用 `quality`，这是对的，但要 A/B |
| with_audio 默认 | `false` | 壁纸不需要音频，保持关闭 |

来源：

- [CogVideoX-3 模型文档](https://docs.bigmodel.cn/cn/guide/models/video-generation/cogvideox-3.md)
- [视频生成异步 API](https://docs.bigmodel.cn/api-reference/模型-api/视频生成异步.md)

官方 CogVideoX-3 页面里的示例提示词是中文的，例如“花瓣被风吹起，不断的旋转变成一个人”“龙王转成敖丙，水墨风晕染……”。这说明新模型对中文并不排斥；但开源 CogVideoX 的官方 i2v 脚本要求英文。**语言不要凭感觉站队，要做同图 A/B。**

### 1.4 社区图生视频指南：公式可用，但镜头部分要改

社区 i2v 指南给的通用公式是：

```text
[主体保持] + [主体动作] + [镜头运动] + [场景氛围/光线] + [约束]
```

来源：[Image-to-Video Prompt Guide](https://github.com/Ninglz/image-to-video-ai-guide/blob/main/docs/prompt-guide.md)

这套公式适合人物、产品、广告，但**动态壁纸不能照抄“镜头运动”**。壁纸要的是“画面里的东西自己动”，不是“镜头带着画面动”。所以我们的公式要改成：

```text
[场景锚点] + [前景实体动作] + [中景实体动作] + [天空/远景动作] + [固定机位] + [保持约束] + [连续运动]
```

社区资料里还有几条可以直接用：

- 一条提示词只保留 **3~5 个元素**，超过 5 个模型会过载、糊、变形；
- 用 **active verbs**，不要用 `moves / goes / happens`；
- 图生视频不要重描述视觉，图片已经给了外观，提示词把动词留给运动；
- 加约束：不要水印、不要文字、不要额外物体、不要脸部变形；
- 约束不要堆太多，互相矛盾的约束会抵消。

来源：

- [Image-to-Video Prompt Examples](https://github.com/Ninglz/image-to-video-ai-guide/blob/main/examples/prompts.md)
- [AI 视频提示词工具包](https://github.com/cclank/lanshu-awesome-ai-video-kit)

### 1.5 资料之间的四个矛盾，怎么取舍

| 矛盾 | 普通视频/社区建议 | 动态壁纸应该怎么做 |
|---|---|---|
| 镜头 | 缓慢推近、环绕、横移更可靠 | **固定机位**；镜头运动一律不写 |
| 结尾 | `then settles back` 防止死循环 | 壁纸要**持续运动到最后一帧**，不要求停住 |
| 循环 | 写 `seamless loop` | 不依赖文字；播放器做 0.6~1.0s 交叉淡化 |
| 长度 | 越长越详细 | 512 字符硬上限；英文 75~85 词，信息密度优先 |

## 2. 为什么现在的片子会“只动光影 / 推镜 / 变暗”

### 2.1 只动光影

如果你只写“阳光闪烁、树影摇晃、氛围感”，模型最容易生成的就是**全局亮度变化**，因为这是最省力的“运动”。它不需要理解草、树叶、车流各自的物理运动。

解法：至少写 2~3 个**实体**，并且把前景实体放在第一句。光影只能作为次要效果，不能当主运动。

### 2.2 镜头自己往前推

模型在训练数据里见过大量“缓慢推近”的图生视频。你一旦写 `cinematic`、`dynamic`、`camera moves`、`dolly in`，它就会用推镜制造运动。更隐蔽的是：即使你不写运镜，只写“让画面动起来”，模型也可能默认推近。

解法：明确写固定机位，并且**不要出现任何运镜词**。固定机位句放在运动清单之后，不要放在第一句抢走注意力。

### 2.3 画面变暗

`sunset`、`dusk`、`golden hour`、`warm sunlight`、`dramatic lighting` 这些词会把模型带向整体色调和曝光变化。图生视频模型还可能为了“电影感”主动压暗画面。

解法：运动提示词里只写地点、地形、实体；不写时间、光线、色调、mood。另加一句“保持原图曝光和色彩”。原图的光线已经存在，不需要再描述。

### 2.4 首尾不接

AI 视频模型不是循环模型。即使写 `seamless loop`，它也不知道“最后一帧要等于第一帧”。首尾帧模式又容易把运动压成静帧，因为模型会优先满足“最后一帧等于第二张图”。

解法：单图模式 + 持续运动 + 播放器交叉淡化；首尾帧只用于明确的转场，不用于自然壁纸。

### 2.5 约束句吃掉了运动预算

这是改造前最容易被忽略的问题。按 2026-10-17 改造前的代码：

- `MOTION_STATIC_LINE` 约 **87 字符**；
- `MOTION_LOOP_TAIL` 约 **164 字符**；
- `MOTION_LAST_FRAME_LINE` 约 **51 字符**。

单图模式光固定句就占 **251 字符**，首尾帧模式占 **215 字符**。512 字符里只剩 260~300 字符给场景和元素，大约 40~45 个英文词。再要求 4~5 个元素、每个 8~16 词，**根本放不下**，`compose_scene_caption` 只能提前 `break`，把后面的元素丢掉。P0/P1 已把固定开销降到单图 153、首尾帧 100 字符。

这会直接造成：

- 元素数量不够，画面只剩光影；
- 场景锚点被压缩，模型自由发挥；
- 固定机位句很强，但运动描述被挤掉。

解法见第 4 节：缩短固定句，或者把固定机位句放到元素之后，并给元素留出至少 300 字符。

## 3. 七段式提示词模板

### 3.1 第一段：场景锚点（10~16 词）

只写“地点 + 地形 + 主要实体”，不写时间、光线、色调、mood。

好：

```text
A dense forest with a winding dirt path, thick ferns and tall trees.
```

坏：

```text
A beautiful sunset forest with warm golden light and a dreamy atmosphere.
```

坏在哪里：`sunset / golden light / dreamy` 会让模型整体调色、压暗、加光晕，而不是让草和树叶动。

### 3.2 第二段：前景运动（1 个主运动 + 1 个次运动）

前景是离镜头最近、面积最大、最容易看出“活”的物体。优先写草、蕨类、花、衣摆、头发、雨滴、地面水花。

```text
In the foreground, ferns bend deeply in visible waves from left to right.
```

```text
In the foreground, loose strands of hair lift and stream to the right.
```

要求：

- 一个主语 + 一个现在时强动词；
- 必须有方向或幅度；
- 不要用 `gently / softly / subtly / slightly / faintly` 形容主运动。

### 3.3 第三段：中景运动（1~2 个实体）

中景写树、车、人、窗帘、火焰、设备、家具。中景是“场景真的在运转”的关键。

```text
In the midground, branches sway in broad arcs and leaves rustle continuously.
```

```text
In the midground, pedestrians walk steadily from left to right, coats and hair moving.
```

### 3.4 第四段：天空/远景运动（1 个环境运动）

天空只写一个，不要抢前景的戏。云、鸟、雾、雪、极光都可以。

```text
In the background, thin clouds stream steadily across the sky.
```

```text
In the background, seabirds glide and flap across the sky.
```

### 3.5 第五段：固定机位（放在运动清单之后）

推荐短句：

```text
Camera locked off; framing, perspective and scale never change.
```

更强但更长的版本：

```text
The camera remains locked off on a tripod; framing, perspective and scale never change.
```

不要写：

```text
Slow cinematic dolly-in, gentle orbit, subtle handheld movement.
```

### 3.6 第六段：保持约束（短而硬）

推荐 1~2 句，控制在 60~100 字符：

```text
Keep composition, exposure and colors; no new objects, text or watermark.
```

人物场景换成：

```text
Keep the same face, clothing and proportions; no new objects, text or watermark.
```

风格场景换成：

```text
Keep the original ink-wash style, composition and colors; no new objects, text or watermark.
```

### 3.7 第七段：连续运动尾巴（10~16 词）

推荐：

```text
Every mover keeps moving continuously to the last frame; never freeze.
```

不要写：

```text
Every motion returns to its starting pose; the last frame matches the first.
```

后半句会把 10 秒片子压成静帧。

## 4. 512 字符预算：先给运动留位置

### 4.1 英文词数与字符数

英文平均一个词约 6~7 个字符（含空格）。512 字符大约是 **75~85 个英文词**。所以：

- 不要写 120 词；会被截断；
- 55~85 词的现有目标是合理的；
- 真正的问题不是“词太少”，而是**约束句占了太多字符**。

### 4.2 推荐预算表

| 段落 | 目标 | 字符预算 |
|---|---|---|
| 场景锚点 | 10~16 词 | 70~110 |
| 前景运动 | 1~2 句 | 60~100 |
| 中景运动 | 1~2 句 | 60~100 |
| 天空/远景 | 1 句 | 45~70 |
| 固定机位 | 1 句 | 50~70 |
| 保持约束 | 1~2 句 | 50~90 |
| 连续运动 | 1 句 | 50~70 |
| **合计** | **70~90 词** | **385~610** |

超过 512 时，按这个顺序砍：

1. 先砍最弱的天空元素；
2. 再砍中景的第二个元素；
3. 保留前景主运动、固定机位、连续运动；
4. 不要砍到只剩光影。

### 4.3 当前代码的预算修正建议

把三句固定话缩短，实际多出 **125 字符**（固定机位保留三脚架版本，语气不降太多）：

| 常量 | 当前 | 建议 | 省下 |
|---|---|---|---|
| `MOTION_STATIC_LINE` | 87 字符 | `Camera locked off on a tripod; framing, perspective and scale never change.`（77） | 10 |
| `MOTION_LOOP_TAIL` | 164 字符 | `Every mover keeps moving continuously to the last frame; never freeze.`（76） | 88 |
| `MOTION_LAST_FRAME_LINE` | 51 字符 | `End on the second image.`（24） | 27 |

这样单图模式的固定开销从 251 降到 153 字符，留给场景+元素约 **357 字符**；首尾帧模式从 215 降到 100 字符，留给场景+元素约 **410 字符**。足够写 3~4 个实体。

代价是固定机位的“语气”变弱。建议做 A/B：

- A：长固定句（强锁镜头，但元素少）；
- B：短固定句（元素多，可能轻微推镜）；
- C：长固定句 + 单图模式 + 减少元素数量。

如果 B 仍然推镜，再恢复长句；不要一开始就用长句把运动预算吃光。

## 5. 实体运动词库

### 5.1 植物

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 草 | `grass sways gently` | `grass bends deeply in visible waves from left to right` | 草是前景首选，幅度要大 |
| 蕨类 | `ferns move` | `ferns bend deeply and ripple in visible waves` | 蕨类叶片大，适合做前景主运动 |
| 树叶 | `leaves move` | `leaves shake and rustle continuously` | 加 `rustle` 让模型理解细碎运动 |
| 树枝 | `branches sway` | `branches sway in broad arcs` | `broad arcs` 给幅度 |
| 花/花瓣 | `flowers move` | `flowers and petals flutter and tumble across the frame` | 适合微风、樱花、花瓣雨 |
| 竹子 | `bamboo sways gently` | `bamboo leaves sway strongly back and forth` | 国风场景常用 |
| 芦苇/麦浪 | `reeds move` | `reeds ripple in visible waves across the field` | 大面积横向运动 |

### 5.2 水、雨、雪、雾

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 湖面 | `water ripples` | `ripples spread outward in overlapping rings` | 方向明确，避免整片水闪 |
| 海浪 | `waves move` | `waves roll steadily toward the shore; foam spreads over the rocks` | 两个动作：浪+泡沫 |
| 瀑布 | `waterfall falls` | `water pours downward; foam churns at the base` | 上下的运动，别让镜头拉远 |
| 雨 | `rain falls` | `rain falls in steady diagonal streaks; splashes rebound from the pavement` | 雨丝+水花，两个实体运动 |
| 雪 | `snow falls` | `snow drifts down in uneven gusts` | `gusts` 给节奏 |
| 雾 | `fog moves` | `mist rolls slowly through the valley, thinning and thickening` | 雾是环境运动，适合中景 |
| 水洼倒影 | `reflections move` | `reflections shimmer and break into moving bands` | 只能做次要运动 |

### 5.3 火、烟、蒸汽

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 火焰 | `fire flickers` | `flames lick upward and flicker; embers rise` | 火焰+火星 |
| 蜡烛 | `candle moves` | `the flame stretches and dances; wax glistens` | 小范围但可见 |
| 烟 | `smoke rises` | `smoke billows upward and drifts to the right` | 方向+体积 |
| 蒸汽 | `steam rises` | `steam rises in twisting ribbons` | 咖啡/热食场景 |

### 5.4 城市、交通、人群

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 车头灯 | `cars move` | `headlights streak continuously along the road` | 光带比“车”更容易出效果 |
| 尾灯 | `traffic moves` | `taillights flow in the opposite direction` | 双向车流更真实 |
| 行人 | `people walk` | `pedestrians walk steadily from left to right, coats and hair moving` | 人群+衣摆 |
| 霓虹 | `neon lights flicker` | `neon signs flicker in a slow irregular rhythm` | 只能做次要；必须有实体 |
| 旗帜 | `flag moves` | `the flag snaps and ripples in the wind` | 布料运动 |
| 路边摊蒸汽 | `steam` | `steam curls upward from the food stalls` | 增加生活感 |

### 5.5 人物、衣摆、头发

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 头发 | `hair moves` | `loose strands of hair lift and stream to the right` | 只动发丝，不动脸 |
| 外套 | `clothes move` | `the coat fabric billows and settles with the wind` | `settles` 是一个小回落，不是停住 |
| 围巾 | `scarf moves` | `the scarf streams and snaps behind the character` | 方向明确 |
| 窗帘 | `curtain moves` | `the curtain swells inward and falls back` | 室内常用 |
| 呼吸 | `person breathes` | `the chest rises and falls slowly and naturally` | 肖像微动 |

### 5.6 天空、远景

| 元素 | 弱/错误写法 | 推荐写法 | 说明 |
|---|---|---|---|
| 云 | `clouds move` | `thin clouds stream steadily from left to right across the sky` | 方向+速度 |
| 飞鸟 | `birds fly` | `birds flap and glide across the sky in a loose flock` | 鸟群 |
| 极光 | `aurora moves` | `aurora curtains ripple and fold across the sky` | 大范围环境运动 |
| 星云 | `stars twinkle` | `a distant nebula shimmers slowly` | 星光单独不算实体 |

> 注意：霓虹、火光、倒影、星光是“光”，不是实体。它们可以做次要运动，但**至少要有 2 个实体主运动**，否则还是“光影呼吸”。

## 7. 负面约束：不要写“不要”，要写“保持”

CogVideoX-3 的视频生成接口当前没有 `negative_prompt` 参数（至少文档里没有）。所以负面约束只能写进 `prompt` 正文，而且要短。推荐用“Keep ...; no ...”的句式，不要堆一长串 `no ... no ... no ...`。

### 7.1 必须避免的运镜词

以下词一旦出现，模型很可能用镜头运动伪造“动态”：

```text
dolly in, dolly out, push in, pull out, zoom, pan, tilt, orbit, tracking shot,
handheld, crane, aerial, parallax, camera moves, cinematic camera movement
```

固定机位只写：

```text
Camera locked off; framing, perspective and scale never change.
```

### 7.2 必须避免的弱词

| 弱词 | 问题 | 替换 |
|---|---|---|
| `gently` | 模型会把动作做得很小 | `steadily` / `visibly` |
| `softly` | 同上 | `visibly` / `continuously` |
| `subtly` | 几乎等于不动 | `clearly` / `strongly` |
| `slightly` | 同上 | `clearly` |
| `faintly` | 同上 | `clearly` |
| `slowly`（主运动） | 容易被理解成慢动作/静止 | `steadily` / `continuously` |
| `moves` | 太笼统 | `bends / sways / streams / ripples / billows` |
| `comes alive` | 没有具体动作 | 直接写实体动作 |
| `dynamic` | 容易触发推镜 | 删掉 |
| `cinematic` | 容易触发推镜和压暗 | 删掉 |

例外：`slowly` 可以用在次要的霓虹闪烁、星云流动上；主运动不要用。

### 7.3 如果工具支持 negative prompt

可以单独放：

```text
camera movement, zoom, pan, tilt, orbit, dolly, tracking, handheld, cuts,
transitions, perspective shift, new objects, text, subtitles, watermark, logo,
style drift, face distortion, extra fingers, duplicated people, flicker,
exposure drift, color shift, freeze
```

但在 CogVideoX-3 里，请把其中最重要的 4~6 个塞进正文，例如：

```text
Keep composition, exposure and colors; no new objects, text or watermark.
```

## 8. 循环接缝：提示词只负责“持续动”，播放器负责“接上”

### 8.1 为什么不要只写 `seamless loop`

CogVideoX 的训练目标是“根据提示词生成一段视频”，不是“生成首尾完全相同的循环视频”。`seamless loop` 对模型来说只是一个普通形容词，不能保证最后一帧等于第一帧。更糟的是，如果你写“回到起始姿态”“最后一帧等于第一帧”，模型可能选择**整段不动**来满足约束。

### 8.2 三层方案

1. **提示词层**：固定机位、3~5 个实体持续运动、不冻结、不让物体进出画面。
2. **生成层**：优先单图首帧；5s 用于测试，10s 用于成片；`quality` 优先，运动不足时再试 `speed`。
3. **播放层**：最后 0.6~1.0 秒交叉淡化回首帧；振荡型运动（草、窗帘、火焰）可以用往返播放；方向型运动（车流、雨、云）用交叉淡化，不要往返。

### 8.3 首尾帧模式：能用，但不适合默认

首尾帧模式的优点：

- 构图被两张图钉死，镜头不容易推；
- 可以明确控制“从 A 变到 B”的转场；
- 循环接缝理论上更可控。

缺点：

- 模型会优先满足“最后一帧等于第二张图”，容易把中间运动压得很小；
- 如果第二张图只是原图的局部位移，模型可能直接“跳”到终点，或者干脆不动；
- `The last frame must match the second image exactly.` 这类硬约束，和“持续运动”天然冲突。

当前代码注释里记录过一次同图对比：首尾帧模式的光流约 **0.06**，单图 `quality` 约 **2.92**，单图 `speed` 约 **8.79**。这不是官方数据，但很能说明问题：**首尾帧很容易把运动压成静帧。**

建议：

- 默认走**单图首帧**；
- 首尾帧只作为“循环锁定/转场”高级选项；
- 如果一定要用首尾帧，把尾帧做成“局部小位移”，并把提示词改成“继续运动到最后一帧，不要提前冻结”，不要写“必须完全匹配”。

### 8.4 循环检查清单

- 镜头有没有推近/缩放？看背景直线是否移动。
- 首帧和尾帧的亮度/色温是否一致？
- 有没有物体在结尾突然消失或进入？
- 主运动在最后一帧是否还在动？
- 交叉淡化 0.8 秒后，接缝是否还能看出来？
- 方向型运动（雨、车流、云）是否被错误地往返播放？

## 9. 故障排查表

| 现象 | 最可能的原因 | 提示词怎么改 |
|---|---|---|
| 只有光影变化，元素不动 | 没有实体主运动；元素太少；弱词太多 | 加 2~3 个实体，前景放第一句；把 `gently/subtly` 换成 `deeply/strongly/continuously` |
| 镜头自己往前推 | 出现 `cinematic/dynamic/dolly/zoom`；固定句太靠后或太弱 | 删掉所有运镜词；把固定机位句放在运动清单后；A/B 长句 vs 短句 |
| 画面变暗/偏色 | 出现 `sunset/dusk/golden hour/warm light`；模型主动压暗 | 场景锚点只写地点和实体；加 `Keep exposure and colors` |
| 首尾不接 | 没有循环处理；首尾帧约束太硬 | 单图模式 + 播放器交叉淡化；首尾帧改成“继续运动到最后一帧” |
| 人物脸变形 | 动作太大；镜头运动；元素太多 | 只动头发/衣摆/呼吸；加 `same face, clothing and proportions`；减到 3 个元素 |
| 画面糊/元素融合 | 元素超过 5 个；动作方向冲突 | 砍到 3~4 个；每个元素只给一个主方向 |
| 画面太乱 | 多个元素都很大幅度 | 一个主运动 + 两个次要运动；主运动写幅度，次要写 `steadily/continuously` |
| 出现文字/水印 | 原图有文字；提示词没约束 | 加 `no text, no watermark`；先清理原图文字 |
| 风格漂移（动漫变写实） | 没有风格锚点 | 加 `Keep the original anime/ink-wash/illustration style` |
| 运动太弱 | `quality` 档偏保守；时长太长；动词太弱 | 试 `speed`；试 5s；动词加方向和幅度 |
| 运动太猛/抽搐 | 动词过强；元素太多；方向冲突 | 减元素；把 `fast` 改成 `steady/continuous`；加 `no flicker` |

A dense forest with a winding dirt path, thick ferns and tall trees on both sides.

## 11. A/B 实测方案：不要一次改完再猜

### 11.1 测试集

选 6 张有代表性的图：

1. 森林/草地（前景植物多）
2. 雨夜城市（雨、车流、人群）
3. 海岸（浪、泡沫、草）
4. 雪山（雪、松枝、云）
5. 人物肖像（头发、衣摆）
6. 室内咖啡（蒸汽、窗帘、雨窗）

### 11.2 变体

| 变体 | 提示词 | 生成模式 | 目的 |
|---|---|---|---|
| A | 当前版本 | 首尾帧 | 基线，确认“静帧”问题 |
| B | 当前版本 | 单图 | 验证单图是否明显更活 |
| C | 重排 + 短约束 | 单图 | 验证预算和顺序 |
| D | 中文版 | 单图 | 验证语言差异 |
| E | C + `speed` | 单图 | 验证 quality/speed 对运动幅度的影响 |

第一轮每张图只跑 A/B/C 三个变体，共 18 条；每条 1 元，约 18 元。不要一上来就跑 6×5×2=60 条。

### 11.3 固定参数

- 同一张图、同一尺寸、同一时长；
- 第一轮统一 5 秒，确认方向后再用 10 秒做最终片；
- `with_audio=false`；
- 水印关闭；
- 记录每次的 `prompt`、模式、quality、duration、任务号。

### 11.4 评价指标

| 指标 | 怎么看 | 目标 |
|---|---|---|
| 前景光流 | 草/树叶/雨/水花是否有明显位移 | 明显高于背景 |
| 全局镜头运动 | 背景直线是否平移/缩放 | 接近 0 |
| 亮度变化 | 首帧/尾帧平均亮度差 | < 5% |
| 循环接缝 | 交叉淡化后是否看出跳变 | 基本看不出 |
| 人工评分 | “活 / 稳 / 像壁纸”各 1~5 分 | 平均 ≥ 4 |

### 11.5 记录表

```text
图片 | 变体 | 模式 | 时长 | quality | 前景运动 | 镜头 | 亮度 | 接缝 | 备注
-----|------|------|------|---------|----------|------|------|------|-----
森林 | A    | 首尾 | 5s   | quality |          |      |      |      |
森林 | B    | 单图 | 5s   | quality |          |      |      |      |
森林 | C    | 单图 | 5s   | quality |          |      |      |      |
```

## 12. 建议的落地顺序

### P0（已完成）：先让画面真的动

1. 默认改单图首帧；
2. 首尾帧作为“循环锁定/转场”高级选项；
3. 保留现有 `VISION_SYSTEM_PROMPT` 的“至少 2 个实体、前景优先”。

### P1（已完成）：再让提示词装得下运动

1. 重排：scene → foreground → midground → sky → camera → constraints → tail；
2. 缩短三个固定句；
3. `compose_scene_caption` 加“丢弃元素”日志；
4. 补测试：<=512 字符、至少 2 个实体句、固定机位句在元素之后、无运镜词。

### P2（待实测）：再做语言和档位 A/B

1. 同一张图跑英文 vs 中文；
2. 同一张图跑 `quality` vs `speed`；
3. 同一张图跑 5s vs 10s；
4. 只保留数据最好的组合，不要凭感觉。

### P3（待做）：最后做循环和 UI

1. 播放器 0.8 秒交叉淡化；
2. 振荡型运动可选往返播放；
3. UI 标明当前是“自然动态”还是“循环锁定/转场”；
4. 如果换到支持 `negative_prompt` 的模型，把负面约束移出正文。

## 13. 速查卡

### 写

```text
foreground: ferns bend deeply in visible waves from left to right
midground: branches sway in broad arcs; leaves rustle continuously
background: thin clouds stream steadily across the sky
camera: locked off; framing, perspective and scale never change
keep: composition, exposure and colors; no new objects, text or watermark
continuity: every mover keeps moving to the last frame; never freeze
```

### 不写

```text
cinematic, dynamic, come alive, beautiful, epic
dolly in, push in, zoom, pan, tilt, orbit, tracking, handheld, crane
sunset, dusk, golden hour, warm sunlight, dramatic lighting
seamless loop, returns to starting pose, last frame matches first
gently, softly, subtly, slightly, faintly（主运动）
```

### 一句话

> **镜头不动，前景先动；写实体，不写光影；写方向，不写形容词；512 字符里先给运动留位置。**
